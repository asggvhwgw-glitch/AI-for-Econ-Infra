# Security and sensitive data

Do not submit credentials, personal data, proprietary datasets, or exploit-ready
payloads to public issues. Use GitHub private vulnerability reporting on the
canonical repository once its maintainers enable that feature. This archive
does not invent a security email address or claim a response-time commitment.
Until a private contact is available, report only a non-sensitive high-level
issue and request a private reporting channel.

Security reports and ordinary statistical correctness reports are different.
A suspicious coefficient, invalid standard error or failed convergence should
use the parameter-only error report template; never include the original data.
Only the current development release is under active review here; no historical
security-support or independently audited security certification is claimed.
